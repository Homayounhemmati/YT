---

## بخش ۱ — چرا مالیات، country-level است نه city-level

- هزینه‌ی زندگی بین شهرهای یک کشور تفاوت زیادی دارد (لندن vs منچستر) → مدل city-level برای cost-of-living درست است.
- مالیات بر درآمد معمولاً در سطح ملی تعیین می‌شود، نه شهر. برلین و مونیخ (هر دو آلمان) یک نرخ فدرال مالیاتی دارند؛ تفاوتشان فقط در هزینه‌ی زندگی است.
- **آمریکا استثناست**، نه قاعده — به‌خاطر ساختار فدرالش (state income tax جدا). این در دیتاست فعلی (۵۱ استیت) مدل شده و باید همان‌طور بماند.
- نتیجه: برای گسترش بین‌المللی مالیات، واحد جدید **کشور** است، نه شهر.

---

## بخش ۲ — دیتاست جدید: مالیات فریلنسری در سطح کشور

از همان ۲۵ کشوری استفاده می‌شود که برای cost-of-living انتخاب شد (سند اصلی، بخش G) — یعنی یک دیتاست، دو منظوره.

### فیلدهای جدید که به آبجکت Country اضافه می‌شوند

```
Country (نسخه‌ی گسترش‌یافته)
  ...فیلدهای موجود (slug, name, region, avgIndex, avgRent, ... , currency, note)

  // فیلدهای مالیاتی جدید:
  incomeTaxStructure     // "flat" | "progressive" | "none" (به‌ندرت)
  incomeTaxRateRange     // [min, max] — بازه، نه عدد دقیق (به دلیل پیچیدگی residency)
  selfEmploymentNote      // پاراگراف کوتاه توضیح قواعد فریلنسری/self-employed
  socialSecurityRate      // درصد تقریبی بیمه‌ی اجتماعی/سلامت اجباری (در صورت وجود)
  digitalNomadVisa        // boolean — آیا ویزای نومد دیجیتال دارد؟
  taxResidencyThreshold   // معمولاً "183 days" یا قانون مشابه کشور
  taxNote                 // پاراگراف یکتا برای سئو + دیسکلیمر محلی
```

### چرا بازه (range) نه عدد دقیق
مالیات بین‌المللی فریلنسری به وضعیت اقامت مالیاتی (tax residency)، قرارداد مالیاتی دوجانبه (tax treaty) بین کشور مبدا و مقصد، و مدت اقامت بستگی دارد. دادن یک عدد قطعی گمراه‌کننده و از نظر حقوقی پرریسک است. راه‌حل: بازه + راهنمای مفهومی، نه محاسبه‌گر دقیق مثل نسخه‌ی آمریکا.

### توابع کمکی جدید
- `getCountryTaxInfo(countrySlug)`
- `getSimilarTaxCountries(slug, limit=6)` — بر اساس میانگین `incomeTaxRateRange`

## بخش ۳ — صفحه و ابزار جدید: Country Tax Guide

**تفاوت کلیدی با State Tax Calculator آمریکا:** این یک "calculator" دقیق نیست، بلکه یک **"guide" با تخمین بازه‌ای** است.

```
مسیر: /tools/freelance-tax-calculator/country/:countrySlug
```

### ساختار صفحه
1. Intro — وضعیت کلی مالیاتی کشور برای فریلنسر/رموت‌ورکر
2. Estimator (نه Calculator دقیق) — ورودی: gross income تقریبی → خروجی: بازه‌ی تخمینی مالیات (`incomeTaxRateRange` × income) با پیام واضح "این یک تخمین است، نه محاسبه‌ی دقیق"
3. بخش «Self-employment rules» (۲۰۰-۳۰۰ کلمه) از `selfEmploymentNote`
4. بخش «Digital nomad visa» — اگر `digitalNomadVisa === true`، توضیح مختصر شرایط
5. بخش «Tax residency» — از `taxResidencyThreshold`
6. FAQ (طبق بخش ۴ پایین)
7. **دیسکلیمر قوی‌تر از نسخه‌ی آمریکا:** «این صفحه محاسبه‌ی حقوقی یا مالیاتی رسمی نیست. برای تصمیم‌گیری واقعی حتماً با یک مشاور مالیاتی محلی یا متخصص مالیات بین‌المللی مشورت کنید.»

---

## بخش ۴ — `buildCountryTaxFaq(country)` — ۵ سؤال

۱. فریلنسرها در {country} چطور مالیات می‌دهند؟ (`incomeTaxStructure` + `selfEmploymentNote`)
۲. نرخ مالیات تقریبی چقدر است؟ (`incomeTaxRateRange` به‌صورت بازه، با تأکید بر تخمینی‌بودن)
۳. چه زمانی فرد از نظر مالیاتی «مقیم» این کشور محسوب می‌شود؟ (`taxResidencyThreshold`)
۴. آیا ویزای نومد دیجیتال دارد؟ (`digitalNomadVisa`)
۵. نکات مهم دیگر؟ (`taxNote`)

## بخش ۵ — تغییرات لازم در ساختار موجود

| بخش سند اصلی | تغییر |
|---|---|
| بخش C (رجیستری ابزارها) | افزودن ورودی جدید: `freelance-tax-country-guide` |
| بخش G (دیتاست کشور) | افزودن ۷ فیلد مالیاتی بالا به آبجکت Country موجود |
| بخش I (رجیستری Programmatic) | افزودن سومین کانفیگ programmatic: `freelance-tax-country` |
| بخش M (مسیریابی) | افزودن `/tools/freelance-tax-calculator/country/:countrySlug` |
| بخش L (الزامات محتوا) | این صفحات هم باید ۸۰۰-۱۲۰۰ کلمه داشته باشند، با تأکید بیشتر روی بخش دیسکلیمر |

**نکته مهم:** دیتاست کشور دیگر فقط برای cost-of-living نیست — یک آبجکت واحد Country حالا هم پایه‌ی صفحه‌ی cost-of-living است هم پایه‌ی صفحه‌ی tax guide. یعنی هر کشور می‌تواند به‌جای دو صفحه‌ی جدا، یک صفحه‌ی ترکیبی «Freelancing in {country}: Cost of Living & Taxes» هم داشته باشد (اختیاری، فاز ۲).
